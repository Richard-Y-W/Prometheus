# Validation policy

Software verification, manufacturer comparison, physical validation, and system validation are distinct. A passing software test does not validate a physical model. Findings use `pass`, `warning`, `fail`, `indeterminate`, `not_applicable`, or `not_run`; errors and missing dominant inputs never become passes.

Critical inputs require accepted evidence and applicable test conditions. LLM confidence is not engineering confidence. Reproducibility records schema, component revisions, artifact hashes, checker/solver versions, settings, dependencies, timing, and cache state.
